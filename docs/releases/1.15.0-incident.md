## Incident and recovery

The stable release workflow `30912109348` built and verified the release
artifacts, container, Action, Nix, browser/WASM archive, checksums, and
attestations. Its crates.io step failed because the original source package
could not resolve internal development-dependency versions. The release tag
was immutable, so it was not rewritten.

The recovery workflow `30956348205` used the immutable `v1.15.0` source with a
development-dependency bootstrap overlay and published the missing internal
versions in dependency order. Job `92150191862` completed successfully. The
per-crate inventory is recorded in
[`1.15.0-registry-inventory.json`](1.15.0-registry-inventory.json).

The recovery overlay is an incident receipt, not a claim that the original
tag was edited. Future stable releases must make registry readiness and
per-crate receipts precede a latest GitHub release and mutable alias moves.

## Final consumer proof

Stable consumer workflow `30965258655` passed every required job:

- five published platform binaries;
- checksums and release assets;
- Nix exact-tag build and run;
- released archive-enabled WASM browser ZIP smoke;
- exact Action binary packet;
- exact Action container packet;
- fail-closed aggregate receipt.

Alias promotion workflow `30965139577` passed exact digest verification,
promotion of `1.15.0`, `1.15`, `1`, and `latest`, and movement of Action `v1`.
All GHCR aliases resolve to the digest above, and `v1` resolves to the stable
source commit. A local Docker Desktop packet run was unavailable because the
Linux engine was not running; the hosted exact-container and Action packet
receipts are the authoritative container evidence.

The clean external install proof passed:

```text
cargo install tokmd --version 1.15.0 --locked
tokmd --version                       -> tokmd 1.15.0
tokmd packet generate --no-syntax .   -> complete packet
```

The full local workspace test and `cargo xtask publish --dry-run` were not
claimed: concurrent Windows Cargo workload caused the isolated attempts to
time out during package validation. Hosted release and consumer checks remain
the release-surface evidence; these local commands are a follow-up proof-cost
issue for the 1.15.1 process.

## Controls for 1.15.1

- Publish and inventory all crates before creating a latest GitHub release.
- Keep stable alias promotion globally serialized and semver-validated.
- Require an exact verified digest, anonymous version/content smoke, and a
  protected release environment before moving mutable aliases.
- Emit a per-crate registry receipt and a single fail-closed consumer receipt.
- Keep the publication repository as the only tag, release, registry, GHCR,
  and Action-alias authority.

## Claim boundary

This incident record proves the released 1.15.0 consumer surfaces listed
above. It does not make a UB-absence claim, promote syntax/AST/mutation/
coverage evidence, or make inactive package-manager templates supported.
